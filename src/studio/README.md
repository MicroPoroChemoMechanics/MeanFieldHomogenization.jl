# MFH Studio

MFH Studio, a local web interface to MeanFieldHomogenization, shipped with the
package as the submodule `MeanFieldHomogenization.Studio`. Users start it with
`using MeanFieldHomogenization; mfhstudio()`; the user guide is the page *MFH
Studio* of the documentation. This file is for those who work on the studio.

## How it is built

- **The server** runs in the user's session: an HTTP.jl server on the loopback
  interface. Every `/api` call carries the random token of the session and
  comes from the studio's own page (`Host` and `Origin` checked, JSON only);
  static files are guarded against `..`. MeanFieldHomogenization is loaded
  there, so the catalog of schemes (`catalog.jl`), the 3-D views
  (`geometry.jl`) and the reading of a script (`parse.jl`, `readback.jl`) are
  computed in the session, at once.
- **The compute process** is a second Julia process (Malt.jl) in the
  environment `@mfh-studio`, which the first launch creates with the very
  MeanFieldHomogenization running (that version pinned, or the clone
  developed), TensND and Plots. It includes `worker/boot.jl` and runs the
  scripts (`worker/run.jl`), each in a fresh module, from an empty folder. It
  can be interrupted, killed and restarted, and keeps its compilation between
  runs; a run is refused when the machine cannot spare the memory.
- **The model** (`model.jl`) is a graph of cells (RVEs and laminates), with the
  parameters, the sweep, the sensitivity and the aging viscoelastic run; the
  page edits it, the server keeps it. `codegen.jl` writes the script it stands
  for and embeds the model at the end, so that the studio reopens it exactly.
- **Text compatible with the Python studio.** The studio was first written in
  Python. Its scripts carry numbers written by Python's `repr` and a model
  written by `json.dumps(…, indent = 1, sort_keys = True)`: `pyformat.jl`
  writes them the same way, so that those scripts read back unchanged. The port
  was checked against the Python studio on a corpus of its tests, examples,
  demo scripts and random models: the scripts identical byte for byte.
- **The 3-D views** are built from the model by the package's own
  constructors; no text the page sends is ever evaluated. A size or an angle is
  a number, or an arithmetic expression of numbers and of the model's
  parameters (`geometry.jl`, `numeric`).
- **`core/`** holds what any studio needs and never refers to homogenization:
  memory, browser, environment, compute process, server, launcher. It is a copy
  of ChemistryLab Studio's core; the two studios are independent.
- **The page** (`web/`) is plain JavaScript without a build step; the vendored
  libraries are listed in `web/vendor/README.md`.
- **English and French.** A text the page shows is written in English inside
  `t("…")` (`web/i18n.js`), or marked `data-i18n` in `index.html`; its French
  goes into `web/i18n/fr.json`, keyed by the English. The labels and notes of
  the catalog are translated the same way. `test_i18n.jl` extracts them all
  and fails on a text without its French, or on a French entry nothing uses.
  The script, its comments and the messages from Julia stay in English.
- **The library** (`library/`) holds the worked examples, each regenerated by
  the tests from its own model (`library.jl`).
- **Echoes scripts** (`.py`) are translated by `tools/echoes2mfh` in a Python of
  their own when one is there (`convert.jl`); nothing else needs Python.

## Screenshots

The screenshots of the documentation and of the README are taken from a studio
just started by `tools/screenshots.mjs` (Node and playwright-core), in the
light and the dark theme, then reduced to 256 colors:

```bash
node src/studio/tools/screenshots.mjs --url 'http://127.0.0.1:8765/?token=…'
```

## Tests

The tests are `test/Studio/`, the `Studio` group of the suite (`core` part);
alone, from the root of the repository:

```bash
julia --project=. -e 'include("test/Studio/runtests.jl")'
```

The tests of the compute process need an environment holding
MeanFieldHomogenization, TensND and Plots, named by `MFHSTUDIO_WORKER_PROJECT`;
without it they are skipped. A run with coverage measures the compute process
too, in the same mode.
